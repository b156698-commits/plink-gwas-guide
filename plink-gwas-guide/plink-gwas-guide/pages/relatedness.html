Relatedness / PI_HAT

01

這一步在做什麼？

Relatedness 檢查用來評估不同 samples 之間的遺傳相似程度。 在 GWAS 中，如果資料中包含未預期的近親樣本、重複樣本或其他高度相關個體， 可能會影響後續統計分析，因此通常需要先辨認這些 sample pairs。

PLINK 1.9 的 --genome 會計算 pairwise IBS / IBD 資訊， 並輸出包含 Z0、Z1、Z2 與 PI_HAT 等欄位的報告。

02

為什麼通常先做 LD Pruning？

PLINK 官方文件指出，--genome 的 IBD calculation 並不會自動考慮 LD， 因此通常建議在計算 relatedness 前先進行某種形式的 LD-based pruning。

→
LD Pruning 建立較相互獨立的 SNP set

03

PLINK 指令

計算 pairwise relatedness plink --bfile step5_ld_pruned --genome --out relatedness

執行後會產生 relatedness.genome， 每一列代表一對不同 samples 的 IBS / IBD 計算結果。

選擇性用法：只輸出 PI_HAT 達某門檻的 pairs plink --bfile step5_ld_pruned --genome --min <PI_HAT threshold> --out relatedness

--min 的數值應依研究目的決定。本網站不把某一個 PI_HAT cutoff 視為所有 GWAS 都必須採用的固定標準。

04

PI_HAT 是什麼？

PLINK 定義
PI_HAT = Z2 + 0.5 × Z1

其中 Z0、Z1、Z2 分別代表一對 samples 共享 0、1、2 個 identity-by-descent（IBD）alleles 的估計機率。

因此 PI_HAT 可以視為一個 pairwise IBD sharing 的摘要值。 PI_HAT 越高，代表兩個 samples 的遺傳相似程度越高； 但實際要採用什麼門檻來決定是否移除其中一人，仍需依研究設計決定。

05

輸出結果怎麼看？

欄位 意義
FID1 / IID1 第一個 sample 的 family ID / individual ID
FID2 / IID2 第二個 sample 的 family ID / individual ID
Z0 估計共享 0 個 IBD allele 的機率
Z1 估計共享 1 個 IBD allele 的機率
Z2 估計共享 2 個 IBD alleles 的機率
PI_HAT IBD sharing 摘要值：Z2 + 0.5 × Z1
06

完整範例

延續上一頁的 LD-pruned dataset：

plink --bfile step5_ld_pruned --genome --out relatedness

接著查看輸出的：

relatedness.genome

再依 PI_HAT、研究設計與樣本資訊判斷哪些 sample pairs 需要進一步確認。若最後決定移除某些 samples，應另外建立 sample removal list， 再使用例如 --remove 的方式處理。

07

注意事項

  • --genome 不會自動替研究者決定要移除哪一個 sample。
  • PLINK 官方文件指出 --genome 的 IBD calculation 不具 LD-awareness，因此通常建議先進行 LD-based pruning。
  • --genome 的計算使用 autosomal SNPs；chrX、chrY 與 chrM 不包含在這項計算中。
  • PI_HAT cutoff 並沒有唯一標準，應依研究目的、樣本設計與後續分析策略決定。
  • 若樣本原本就包含已知 family structure，解讀 relatedness 時也應結合 pedigree / sample metadata。
