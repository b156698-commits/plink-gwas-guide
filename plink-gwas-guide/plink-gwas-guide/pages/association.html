Association Analysis

完成基本 QC 後，以 case-control phenotype 為例， 將 phenotype、covariates 與 PCA principal components 放入 logistic regression， 檢驗各 variant 與疾病狀態之間的 association。

01

分析概念

對 case-control GWAS 而言，常見的目標是檢驗每個 variant 的 genotype 是否與 case / control status 有關，同時控制 age、sex、principal components 等可能的 covariates。

Genotype 每個 variant 的 allele dosage
+
Covariates Age、Sex、PCs ...
→
Logistic Model Case / Control outcome
02

Association Analysis 要使用哪一份資料？

前面的 LD pruning 主要是為 PCA、relatedness 等分析建立較相互獨立的 SNP set。 正式 GWAS association testing 通常不應只剩下 LD-pruned SNPs。

比較常見的做法是：

LD-pruned dataset 用於 PCA / Relatedness
Full post-QC dataset 套用 sample QC 後，用於 genome-wide association testing

因此 PCA 可以從 LD-pruned SNPs 計算 PCs，再把這些 PC scores 合併到 covariate file；association analysis 則回到經過 variant / sample QC 但保留 genome-wide variants 的資料。

03

Phenotype 檔案

PLINK 可以從 .fam 讀取 phenotype，也可以使用 --pheno 載入額外的 phenotype file。

Case-control phenotype 的常見 PLINK 1.9 編碼為：

值 意義
1 Control / unaffected
2 Case / affected
-9 或 0 Missing phenotype

例如：

FID IID STATUS
F001 I001 1
F002 I002 2
F003 I003 1
F004 I004 2
指定 phenotype --pheno phenotype.txt --pheno-name STATUS
04

Covariates

--covar 可載入 covariate file。前兩欄應為 FID、IID， 後面的欄位則放入想控制的 covariates。

例如：

FID IID AGE SEX PC1 PC2 PC3
F001 I001 65 1 -0.012  0.021 -0.004
F002 I002 72 2  0.008 -0.016  0.011
F003 I003 69 1 -0.006  0.005  0.007
F004 I004 74 2  0.015 -0.009 -0.010
指定 covariates --covar covariates.txt --covar-name AGE,SEX,PC1-PC3

這裡使用 AGE、SEX、PC1–PC3 只是教學範例。 真正要控制哪些 covariates，以及需要多少 PCs，應依研究設計決定。

05

Case-Control Logistic Regression

完整範例 plink --bfile qc_final --pheno phenotype.txt --pheno-name STATUS --covar covariates.txt --covar-name AGE,SEX,PC1-PC3 --logistic hide-covar --out gwas_logistic

--logistic 會對 case-control phenotype 執行 logistic regression。 在沒有另外指定 dominant、recessive 等 modifier 時，主要 SNP effect 使用 additive dosage coding。

--pheno

載入外部 phenotype file。

--pheno-name

指定 phenotype 欄位名稱。

--covar

載入 covariate file。

--covar-name

指定要使用哪些 covariates。

--logistic

針對 case-control phenotype 執行 logistic regression。

hide-covar

不在主要輸出中逐列列出每個 covariate 的 regression result，使結果較精簡。

06

輸出結果

主要結果會輸出到：

gwas_logistic.assoc.logistic
欄位 意義
CHR Chromosome
SNP Variant identifier
BP Base-pair coordinate
A1 Allele 1
TEST Regression test identifier；預設 SNP additive effect 常見為 ADD
NMISS 此 variant 實際納入 regression 的 observations 數
OR Odds ratio；若使用 --logistic beta 則改報 regression coefficient
STAT Regression test statistic
P Association test P-value
07

結果怎麼看？

對每個 variant，最常先關注 OR 與 P。 OR 描述 A1 allele 與 outcome odds 的關係，而 P-value 則用來評估 association evidence。

OR > 1 A1 與較高 outcome odds 相關
OR < 1 A1 與較低 outcome odds 相關
P-value 下一步可搭配 GWAS significance threshold 與 Manhattan plot 判讀

OR 的方向必須配合 A1 allele 一起解讀；不能只看到 OR 大於或小於 1 就忽略 effect allele。

08

注意事項

  • Case-control phenotype 在 PLINK 1.9 中通常以 1=control、2=case 編碼；--1 可改用 0/1 編碼。
  • 若 covariate 有 missing value，實際納入 regression 的 sample 數可能減少，因此需留意 NMISS。
  • Age、sex、PCs 等 covariates 是否納入模型，應依研究設計與資料特性決定。
  • 不要直接使用只剩 LD-pruned SNPs 的資料做完整 genome-wide association testing；LD pruning 與 association testing 的目的不同。
  • --logistic 預設報 odds ratio；若加上 beta modifier，則改報 regression coefficient。
  • 單一 variant 的 P-value 之後仍需要放到 genome-wide multiple-testing 的脈絡下解讀。
