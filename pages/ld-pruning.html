Quality Control · Step 03

LD Pruning

利用 Linkage Disequilibrium（LD）資訊建立較相互獨立的 variant 集合， 常用於 PCA、relatedness 等需要降低高度相關 SNP 影響的分析。

--indep-pairwise --extract

01

這一步在做什麼？

鄰近 variants 之間可能存在 Linkage Disequilibrium（LD），因此彼此具有較高相關性。 LD pruning 的目的不是判斷某個 SNP「好不好」，而是從高度相關的 variants 中保留較相互獨立的一組 markers。

原始 variants 包含許多彼此高度相關的 SNPs
→
LD Pruning 依滑動視窗與 r² 門檻進行篩選
→
Pruned SNP set 較接近 linkage equilibrium 的 marker 集合
02

使用時機

LD-pruned marker set 常被用於需要降低 marker 間高度相關性的分析。 例如 PCA 或 pairwise IBD / relatedness 計算前，常會先建立一組 LD-pruned SNPs。

這裡應區分「建立 pruned marker list」與「真的把 variants 從資料集中刪除」： --indep-pairwise 會先產生 marker 名單，之後可再用 --extract 套用這份名單。

03

PLINK 指令

基本格式 plink --bfile data --indep-pairwise <window> <step> <r2> --out ld
指令格式範例 plink --bfile data --indep-pairwise 50 5 0.2 --out ld

50 5 0.2 是常見的示範寫法，用來說明三個參數的位置； 不代表所有研究都應使用相同設定。

04

三個核心參數

1

Window size

第一個參數指定每次計算 LD 時納入多少 variants。 也可以使用帶有 kb 的 window，例如 500kb。

2

Step size

第二個參數表示每完成一次檢查後，滑動視窗向前移動多少 variants。

3

r² threshold

第三個參數是 pairwise squared correlation 的門檻。 若同一視窗中的 variant pair 超過門檻，PLINK 會逐步 pruning，直到不再有超過門檻的 pair。

05

輸出檔案

ld.prune.in

保留下來的 variant IDs，可作為後續 --extract 的輸入。

ld.prune.out

被 pruning 排除的 variant IDs。

使用 prune.in 建立 LD-pruned dataset plink --bfile data --extract ld.prune.in --make-bed --out data_pruned
06

完整範例

延續前面的 QC 資料，可以先建立 pruning list，再建立 LD-pruned dataset：

plink --bfile step4_hwe --indep-pairwise 50 5 0.2 --out ld

plink --bfile step4_hwe --extract ld.prune.in --make-bed --out step5_ld_pruned

第一行負責計算 pruning list；第二行才利用 ld.prune.in 建立只包含保留 variants 的新資料集。

07

注意事項

  • --indep-pairwise 的三個參數都有分析意義，不應只複製別人的數值而不了解其作用。
  • Window、step 與 r² threshold 的選擇應依研究目的與資料特性調整。
  • LD pruning 常用於 PCA、relatedness 等分析，但不代表所有 association analysis 都必須先以同一方式 pruning。
  • PLINK 1.9 官方文件指出這類 LD-based calculation 只考慮 founders。
